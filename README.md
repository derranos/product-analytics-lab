# Анализ интернет-магазина

Проект разбирает две задачи продуктового аналитика на открытых данных: где посетители теряются на пути к покупке и что можно заключить по результатам эксперимента с контрольной и тестовой группами. Это два отдельных анализа: наборы данных не связаны между собой.

## Что сделано

- В данных Retailrocket проверены обязательные поля, типы событий, повторы и временные границы.
- В PostgreSQL рассчитаны пользовательские сессии и показатели переходов между просмотром, добавлением в корзину и покупкой. Основные результаты и трактовка метрик описаны в отчётах.
- Для просмотра результатов собрана панель в Redash. В папке проекта лежат её снимки.
- На данных ASOS разобран эксперимент `036afc`, вариант `2`, метрика `1`. Посчитаны разница средних, доверительный интервал и p-value и. По последней временной точке статистически значимое различие не обнаружено. Смысл метрики в наборе не раскрыт, поэтому вывод о пользе изменения сделать нельзя.

## Где что лежит

```text
data/raw/retailrocket/events.csv                 события Retailrocket
data/raw/asos/asos_digital_experiments_dataset.parquet  результаты экспериментов ASOS
logs/create_and_check/                           проверка и описание исходных данных Retailrocket
logs/showcases/                                  запросы, отчёты и снимки панели
logs/asos_exp/                                   скрипт, отчёт и графики по эксперименту ASOS
```

В `logs/showcases/description1.txt` описаны основные показатели воронки. В `description2.txt` и `description3.txt` приведены дополнительные варианты расчётов и разбор по дням недели.

## Как воспроизвести

### Анализ Retailrocket

Нужны PostgreSQL и DBeaver (мой случай).

1. Создай базу данных `pa_case` и подключись к ней в DBeaver.
2. Выполни запрос:

   ```sql
   CREATE SCHEMA IF NOT EXISTS raw;

   CREATE TABLE IF NOT EXISTS raw.retailrocket_events (
       "timestamp" BIGINT,
       visitorid BIGINT,
       "event" TEXT,
       itemid BIGINT,
       transactionid BIGINT
   );
   ```

3. Импортируй `events.csv` в таблицу `raw.retailrocket_events`. В файле есть строка заголовков; сопоставь её с колонками таблицы.
4. В DBeaver выполни запросы из файлов в `logs/create_and_check/`, затем `conversion1.sql`, `conversion2.sql` и `day_conversion.sql` из `logs/showcases/`.
5. Чтобы собрать панель заново, добавь в Redash источник PostgreSQL для базы `pa_case`, создай запросы из SQL-файлов и добавь их визуализации на панель. Снимки уже готовой панели находятся в `logs/showcases/`.

### Анализ ASOS

Нужен Python и библиотеки `pandas` для таблиц, `scipy` для статистики, `matplotlib` и `seaborn` для графиков, `pyarrow` для чтения Parquet. Из корневой папки проекта установи библиотеки и запусти скрипт:

```powershell
python -m pip install pandas scipy matplotlib seaborn pyarrow
python logs/asos_exp/exp.py
```

Скрипт выводит таблицу с результатами и открывает графики. Сохранённые изображения графиков и текстовый разбор лежат в `logs/asos_exp/`.
